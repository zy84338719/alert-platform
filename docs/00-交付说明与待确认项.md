## 无法跳过的五项决策

1. **状态权威**：Prometheus/DeepFlow 的 firing/resolved 由上游判定；平台持有镜像与处置状态；HUATUO 发生型事件由平台事件规则聚合。
2. **通知权威**：Shadow 阶段上游通知保持；逐规则切换到统一平台，避免双发。
3. **接收承诺**：直接入口 Kafka 持久化 ACK 后返回 202；Edge 模式本地 fsync ACK 后返回 202，中心 ACK 后才能删除本地数据。
4. **对账语义**：Alertmanager Webhook 不能代替完整的原始状态流；来源断联为 Stale 而非自动 Resolved。
5. **事件与工单隔离**：AlertEvent、AlertInstance、Incident、NotificationTask 四类对象分离，不能用一张表混合。

## 非目标

- 不改造 DeepFlow / Prometheus / HUATUO 本体；不强制直接读取它们的数据库。
- V1.0 不重新实现完整 PromQL、远程写入或监控采集系统。
- V1.0 不引入 OAgentKit/LLM 进入核心状态机和通知仲裁链路。
- V1.0 不承诺外部渠道 Exactly Once 和 SSE 断线期间源端的历史补回。
