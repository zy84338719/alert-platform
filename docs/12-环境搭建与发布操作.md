# 12 · 开发环境、CI/CD 与生产上线指导

## 开发依赖

- Go 版本：`go.mod` 的 `go` 指令为当前基线（2026-11-13 起随 OEKit BOM 升至 1.26.0）。
- **IDL 工具链（BASE-003 已锁版）**：`buf v1.75.0`、`protoc-gen-go v1.36.13-0.2026…`（buf 配对版）、`hz v0.9.8` 均锁定在 go.mod `tool` 指令，经 `go tool <name>` 调用（`make idl-*` 封装），无需全局安装。`protoc`（仅 hz 需要）为 Homebrew libprotoc 36.2。验证：`make idl-check`、`make idl-drift`、`make idl-breaking-drill`。
- OEKit（`github.com/oekit/oekit` BOM v0.6.2 起）随 `go get` 引入，版本记录于 go.mod。
- Kafka：建议本地使用 compose 或 Testcontainers，仅限开发集成测试。
- PostgreSQL：建议 16+ 系列经过 DBA 选型确认后固定；`migrations/0001_initial.up.sql` 需审核再应用。

### PG 集成测试（BASE-005）

```bash
# 默认路径：Testcontainers 自动起 postgres:16-alpine（需要可用的 Docker）
make test-pg
# 外部 DSN 路径：任意一次性 PostgreSQL（本机 Docker 端口转发故障时用 rpi-k3s）
kubectl --kubeconfig ~/.kube/rpi-k3s.yaml apply -f deploy/test/pg-test.yaml
ALERT_TEST_PG_DSN=postgres://postgres:test@10.10.10.20:30543/postgres?sslmode=disable make test-pg
```

两条路径跑同一套断言（两遍迁移不报错、表清单对账、来源记录往返）；外部模式为每个测试建独立随机库并在结束时 DROP（清理失败会使测试红）。

## 本地一键启动（BASE-002 起）

```bash
make dev-up      # 构建并启动 alert-api(:8080)/alert-worker(:8081)/alert-edge(:8082)
                 # 自动验证三者 /healthz 200，并跑 trace_id 跨组件串联演示
make dev-trace   # 对已运行进程重跑 trace 演示
make dev-down    # 停止全部本地进程
```

- 配置基线在 `etc/config.yaml`；优先级 env（`ALERT_API_ADDR`/`ALERT_WORKER_ADDR`/`ALERT_EDGE_ADDR`/`LOG_LEVEL`/`OTLP_ENDPOINT`）> YAML > default。
- 日志为结构化 JSON（slog），`trace_id` 由标准中间件栈自动注入每条 `logx.Ctx*` 日志；`OTLP_ENDPOINT` 为空时不创建导出器（无外联）。
- 进程日志在 `.dev/logs/`，PID 在 `.dev/pids/`（均已 gitignore）。

## 镜像构建（BASE-004）

单镜像三入口（`Dockerfile`，多阶段 `$BUILDPLATFORM` 交叉编译，CGO 关闭，非 root 运行，基础镜像钉版 `golang:1.27.4-alpine` / `alpine:3.21`）：

```bash
docker build -t alert-platform:local --build-arg VERSION=0.1.0-dev+local .
# 运行（默认 entry = alert-api；按组件覆盖）
docker run -d --name api alert-platform:local
docker run -d --entrypoint /usr/local/bin/alert-worker alert-platform:local
# 健康探活：宿主端口转发不可用时从同网络命名空间旁路容器探
docker run --rm --network container:api alpine:3.21 wget -qO- http://127.0.0.1:8080/healthz
# 多架构 + SBOM（BuildKit 原生，SPDX-2.3 attestation 附于 OCI 输出）
docker buildx build --platform linux/amd64,linux/arm64 --sbom=true \
  --output type=oci,dest=image.tar .
```

- 配置：镜像内置 `etc/config.yaml` 基线（WORKDIR `/app`），env 覆盖优先；部署可用 ConfigMap 挂载替换。
- `version` 经 `-ldflags -X main.version=` 注入（CI 用 git short SHA）。
- CI（contract-ci.yml `image` job）：每次构建双平台+SBOM 并归档 OCI artifact；**merge main 推 dev registry 仅在 `DEV_REGISTRY` secret 配置后生效**（未配置时输出 blocker notice，job 其余部分照常验证）。

## 推荐流水线

1. PR 触发：Go format、vet、test、Buf lint/build/breaking、生成代码差异、Schema 测试、依赖扫描。
2. Merge：构建带 commit SHA 的不可变镜像；产出 SBOM、部署 Chart、变更清单。
3. Dev：迁移数据库 -> 灰度部署 -> 集成 E2E -> 观察队列/业务指标。
4. Preprod：压测与 Chaos、DB 备份恢复、边界安全检查。
5. Prod：Shadow -> 小范围交接通知权 -> 扩大灰度 -> Go/No-Go 评审。

## 回滚准则

- 优先回滚应用镜像和流量路由；数据库 Migration 需采用向前兼容 Expand/Migrate/Contract，不保证所有 DDL 可逆。
- 保留 Kafka Consumer/IDL 双向兼容窗口，避免老版本无法读新事件。
- 通知权交接必须可按规则回滚到上游，严禁同时两个系统不受控通知。
- 回滚前确认 PostgreSQL 中仍有待投递任务，避免遗漏或二次发送。

### 备份命令（生产前由 SRE 固化到作业平台）

```bash

kubectl exec -n infra postgres-0 -- pg_basebackup -D /var/lib/postgresql/backup/base -Fp -Xs -P
# WAL 归档（postgresql.conf: archive_mode=on, archive_command 见下）

# 逻辑备份（跨大版本迁移用）
pg_dump --format=directory --file=dump alert_platform
```

### 恢复（任意时间点）

```bash
# 1) restore base backup; 2) copy wal_archive/*; 3) recovery_target_time
echo "restore_command = 'cp /wal_archive/%f %p'" >> postgresql.auto.conf
echo "recovery_target_time = '2026-11-14 12:00:00+08'" >> postgresql.auto.conf
echo "recovery_target_action = 'promote'" >> postgresql.auto.conf
```
