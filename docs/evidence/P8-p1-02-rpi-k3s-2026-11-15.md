# P8-P1-02 NetworkPolicy 真集群验证（rpi-k3s · 2026-11-15）

## 环境

- 集群：rpi-k3s，7 节点全 arm64（k3s v1.37.0+k3s1），kubeconfig `~/.kube/rpi-k3s.yaml`
- Release：`ap-dev`（namespace `alert-platform`），验证前 REVISION 2 → 验证后 **REVISION 3**
- Chart：本地 `deploy/helm/alert-platform` + `deploy/helm/environments/values-dev.yaml`（0.3.0）
- 镜像：`alert-platform:0.3.0-dev`（节点本地导入，集群无 registry、无 SSH 导入通道 —— 本次**仅升级 chart/NetworkPolicy**，未替换镜像）

## 变更内容

`helm upgrade ap-dev`（REVISION 3）将三条 per-component NetworkPolicy 就地更新：

- `ap-dev-alert-platform-worker-np`：新增 **公网通知出口**（TCP 80/443，`0.0.0.0/0` 排除
  10/8、172.16/12、192.168/16、169.254/16、100.64/10；IPv6 `::/0` 排除 fc00::/7、fe80::/10）
- `edge-np`：新增 `edgeCentralNamespace/Port` 可选跨 namespace 中央 API 规则（dev 未启用，保持同 ns）
- `api-np`：不变

Pod 未重启（api/edge AGE 保持 12h，仅 migrate hook 以旧镜像重跑并 Complete；P8 的 0009/0010/0011
迁移需待新镜像导入后应用 —— 见"限制"）。

## 连通性矩阵（实测）

测试工作负载：临时 Pod `p8-nettest-worker`（标签 `instance=ap-dev, component=worker`，镜像同上，已删除）。

| # | 源 | 目标 | 期望 | 实测 |
| --- | --- | --- | --- | --- |
| W1 | worker | 同 ns api:8080 `/healthz` | allow | **200 `{"status":"ok"}`** |
| W2 | worker | DNS `kubernetes.default.svc.cluster.local` | allow | **解析成功 10.45.0.1** |
| W3 | worker | kube-system:53/TCP | allow | **open** |
| W4 | worker | kube-system:9153（非 53 端口） | deny | **立即失败（exit 1，无超时消息）** |
| W5 | worker | LAN 节点 10.10.10.32:22（10/8 被排除） | deny | **立即失败（exit 1）** |
| W6 | worker | 公网 1.1.1.1:443 | allow（策略） | **包已放行，上游超时**（`nc: Operation timed out`；集群无外网） |
| E1 | edge | 同 ns api:8080 `/healthz` | allow | **200 `{"status":"ok"}`** |
| E2 | edge | dev-pg:5432（非 api、非 DNS） | deny | **立即失败（exit 1）** |
| E3 | edge | 公网 1.1.1.1:443 | deny | **立即失败（exit 1）** |
| A1 | api | dev-pg:5432（同 ns） | allow | **连通（real 0m0.00s）** |
| A2 | api | 公网 1.1.1.1:443（无公网规则） | deny | **立即失败（exit 1）** |

判定依据：策略拒绝表现为**立即失败**（无 `Operation timed out`）；策略放行但上游不可达表现为
`Operation timed out`（W6）。据此 W4/W5/E2/E3/A2 = 策略拒绝，W6 = 策略放行（受集群无外网限制）。

## 限制与后续

1. 集群无公网出口（ungoverned pod 直连 1.1.1.1 亦超时）→ worker 通知出口的**真实外呼**需在有外网环境
   复验（飞书/钉钉沙箱，P8-012 / NOTI-002 同源挂账）。
2. 无镜像导入通道（无 registry / 无节点 SSH）→ 本次未部署 P8 运行时二进制与 0009–0011 迁移；
   集群侧验证范围 = Chart/NetworkPolicy 升级路径 + 连通矩阵。P8 应用的集群级验收待镜像通道。
3. `values-dev` 中 worker 未启用（集群暂无 Kafka），用同标签临时 Pod 验证策略；正式 worker 上线后复跑 W1–W6。

## 复现

```bash
export KUBECONFIG=~/.kube/rpi-k3s.yaml
helm upgrade ap-dev deploy/helm/alert-platform -n alert-platform \
  -f deploy/helm/environments/values-dev.yaml
kubectl get networkpolicy -n alert-platform ap-dev-alert-platform-worker-np -o yaml
# 临时 worker 标签 Pod + nc/wget 矩阵（命令同上表；测完 kubectl delete pod）
```
