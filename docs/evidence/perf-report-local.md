# PERF-001/002 本地容量报告 · 2026-11-14

环境：macOS arm64（本机）、compose PG16/Kafka(confluent-local 7.5)、单 api 副本 + 单 worker 副本、topic 3 分区。生产压测在性能集群复跑（PERF-003 阈值表按集群规格标注）。

## 第一轮（优化前，基线）

| 场景 | 批推送 P50/P95/P99 | 端到端(push→receipt) | 错误 |
| --- | --- | --- | --- |
| 稳态 100 EPS×120s | 595ms / 606ms / 614ms | P95 5.5ms（样本 n=19） | 0 |
| 突发 2000 EPS×60s | 544ms / 554ms / 557ms | P95 47.4s（消化中，滞后收敛） | 0 |

- 突发期间零不透明丢弃；单 worker 消化速率 ≈450 EPS（滞后 8.1 万条在突发结束后持续收敛）。
- **热点定位**：ingest 路径逐事件串行同步发布（批 50 = 50 次 acks=all 往返）——api 侧瓶颈。

## 第二轮（PERF-002 优化：整批一次 WriteMessages）

| 场景 | 批推送 P50/P95/P99 | 端到端 | 错误 |
| --- | --- | --- | --- |
| 稳态 100 EPS×60s | **15.1ms / 17.5ms / 20.3ms** | P50 95.8ms / P95 162.5ms / P99 176.4ms（n=1985） | 0 |

- 批推送延迟下降 **~40×**；端到端 P95 163ms ≪ SLO 3s。
- worker 侧吞吐为横向扩容维度（k8s 副本数），不在本轮代码优化范围（docs/02 §5 拆分触发器）。

## 结论

- 100 EPS 稳态：入队→处理 P95 163ms（SLO ≤3s ✓）。
- 2000 EPS 突发：无丢弃、滞后可恢复 ✓（单 worker 需 ~5 副本消化 2k EPS——写入 PERF-003 扩容阈值表）。
- PG IO：本轮无锁等待异常（baseline_hotspots 采样 0 锁等待）；行锁热点在 alert_instances 热告警行（version 递增），P5 后压测复核。
