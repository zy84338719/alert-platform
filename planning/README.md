# 研发计划文件使用方法

- `week_schedule.csv`：20 周周级排期，开始于 2026-11-16，固定每周周一至周五。
- `backlog.csv`：按任务 ID / owner / 人日 / 依赖 / 验收标准建立的初始任务树。可导入 GitLab Issues、Jira 或飞书项目（按目标系统列名进行映射）。**逐任务的详细二值验收标准与证据要求以 `docs/13-分阶段任务验收标准.md` 为准**，本表 acceptance 列为摘要。
- `risk_register.csv`：风险跟踪。每次里程碑评审须刷新。
- `DEVELOPMENT_LOG.md`：开发进度日志——每轮研发会话追加（现状审计、变更、验证命令与结果、阻塞、下轮建议），是跨会话接续的权威进度记录。
- `P0-评审纪要-2026-11-13.md`：P0 评审签字与阻塞项记录。

所有 `estimate_person_days` 是**人日估算**，不是某个任务需要的日历天数；一部分研发并行。角色是建议 Owner，不是已分配到实际人员。status 列取值：`TODO` 未开始 / `REVIEW` 交付物就绪待人工评审或签字 / `BLOCKED` 外部依赖未提供 / `DONE` 验收标准全部满足且有证据（判定依据以 `docs/13` 为准）。项目组第一次 Sprint Planning 应按实际成员工时重新拆解并确认依赖。
